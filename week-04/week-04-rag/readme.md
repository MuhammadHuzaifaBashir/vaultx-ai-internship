# NimbusWorks RAG — Week 04 Project

A retrieval-augmented QA system over 5 sample internal policy documents,
using Gemini for embeddings + generation and Chroma as the vector store.

## Setup (run this on your own machine)

```bash
cd rag_project
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# edit .env and paste your Gemini API key
# (get one free at https://aistudio.google.com/apikey)
```

## Run the pipeline, in order

```bash
cd scripts

# 1. Chunk the corpus (already tested, no API key needed)
python 01_ingest_and_chunk.py

# 2. Embed chunks + build the persisted vector index (needs API key)
python 02_build_index.py

# 3. Ask a question
python 03_rag_query.py "How many days of sick leave do I get?"

# 4. Run the evaluation suite (15 answerable + 3 unanswerable questions)
python 04_evaluate.py

# 5. Serve as an API for n8n/Make to call
uvicorn app_api:app --reload --port 8000
# then POST {"question": "..."} to http://localhost:8000/ask
```

## Using your own documents instead

Replace the .txt files in `corpus/` with your own (plain text works out of
the box; for PDFs, extract text first — e.g. with `pypdf` — then save as
.txt into `corpus/`). Re-run steps 1 and 2. Everything downstream just
works, since it doesn't know or care what the documents are about.

## Wiring into n8n (Task 05 from the brief)

1. Start the API: `uvicorn app_api:app --port 8000` (keep it running, or
   deploy it somewhere reachable from your n8n instance).
2. In n8n: Slack Trigger (new message in a channel) → HTTP Request node
   (POST to `http://<host>:8000/ask`, body `{"question": "{{ $json.text }}"}`)
   → Slack node (reply with `{{ $json.answer }}`).
3. Export the workflow as JSON, screenshot a live run — that's your
   deliverable #5 (RAG connected to a live workflow).

## Notes on the sample corpus

Since you didn't have documents ready, I wrote 5 realistic internal policy
docs for a fictional company ("NimbusWorks Inc.") covering leave, IT
security, onboarding, expenses, and remote work — about 40 chunks total.
This is a good size for a first RAG system: big enough to be a real
multi-document retrieval problem, small enough to eyeball and debug. Swap
in your real documents any time; nothing else in the pipeline changes.
